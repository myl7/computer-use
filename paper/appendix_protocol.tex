\section{Online algorithm details}\label{app:protocol-details}

\looseness=-1
Algorithm~\ref{alg:policy} states the execution order, including required source traces, program list control, fallback, and both compilation outcomes.
\begin{algorithm}[htbp]
\caption{PACE with extra-cost margin $\epsilon$.
Family identities, cost profiles, routing charges, and the probability of GUI drift are given.}
\label{alg:policy}
\begin{algorithmic}[1]
\State Initialize cumulative charges $K\gets0$ and agent reference $A\gets0$
\For{each arrival $t$}
\State Load the arriving family's costs and state
\State $A\gets A+\tau_0+c$
\State Remove idle list entries and add the family's saved program if it can still be reused before the budget check
\State Compute $U_t^{\mathrm{serv}}$ from Equation~\ref{eq:service-reserve}
\If{$K+U_t^{\mathrm{serv}}>(1+\epsilon)A$}
\State Clear the program list and select agent service
\EndIf
\State Pay routing and serve the task; on a detected program failure, pay one agent fallback
\State Add the routing and serving charges to $K$; log completed agent traces
\State Stop reusing the program after detected GUI drift and update the task arrival records
\If{at least $k$ agent runs are complete, there is no program to reuse, and Equation~\ref{eq:trigger} holds}
\If{$K+\max(C,C^{\mathrm{fail}})\leq(1+\epsilon)A$}
\State Compile a program and verify it on completed source tasks; increment $j$
\If{verification passes}
\State $K\gets K+C$; increment $g$; keep and list the program
\Else
\State $K\gets K+C^{\mathrm{fail}}$
\EndIf
\EndIf
\EndIf
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Compilation spend}
\label{app:reference}
For independent attempts with fixed verification probability $p>0$, the number of failed attempts before the first successful verification has mean $(1-p)/p$.
The expected compilation spend is therefore
\begin{equation}
B(p)=C+\left(\frac1p-1\right)C^{\mathrm{fail}}.
\label{eq:compile-spend}
\end{equation}
Using the estimate from past outcomes $\hat p$ gives PACE's estimated compilation cost $\hat B$.
This calculation excludes agent service between attempts and assumes a fixed retry distribution, which the repeated GUI measurements do not confirm.
The cost guarantee instead counts each actual model charge and does not use this independence assumption.

\subsection{Program lifetime}
\label{sec:program-lifetime}
A replacement calculation explains the lifetime cap $1/h$.
Suppose a working program can be produced at fixed cost $B$.
On each execution, GUI drift independently makes it stop working with probability $h>0$.
A replacement cycle has expected length $1/h$, including the execution on which GUI drift occurs.
It pays $B$, extraction per execution, fallback with probability $q$ conditional on no GUI drift, and one fallback when GUI drift occurs.
Dividing expected cycle cost by expected length gives
\begin{equation}
c^{\mathrm{prog}}+(1-h)qc+h(B+c).
\label{eq:replacement}
\end{equation}
This is below agent cost $c$ exactly when $s_h/h>B$.
At $\hat H=1/h$ with no routing charge, the proposal has the same form, using estimated spend $\hat B$.
Smaller reuse estimates further limit the savings available to repay compilation.
This reference calculation compares two specified policies and does not establish optimal replacement under unknown parameters.

\subsection{Cost of reserving for failure}
\label{app:reservation-example}
Reserving the failed-attempt cost can delay a compilation until observed arrivals add enough budget.
E.g., suppose a proposal passes the savings test in Equation~\ref{eq:trigger}, but success costs $60$ and failure $120$ tokens.
With reference and charged costs both $300$, $\epsilon=0.25$ allows only $75$ additional tokens, so PACE waits to compile.
Two more agent-served arrivals costing $100$ each raise both totals to $500$.
The resulting $125$ allowance covers either outcome.
Only observed arrivals increase this allowance.

When the failed-attempt cost exceeds the allowance for the whole stream, the reservation prevents compilation entirely.
A single-family example has $300$ arrivals, $k=3$, agent cost $1$, successful compilation cost $2$, and possible failed cost $200$.
Set $c^{\mathrm{prog}}=q=h=\tau_0=m=0$.
The compiler succeeds, but the policy does not know that in advance.
With $\epsilon=0.25$, PACE's extra budget never reaches the $200$ reservation, so it uses the agent and pays $300$.
Eager retry pays $3$ for source runs and $2$ for compilation.
The example shows how reserving the failure branch can prevent a profitable compilation while staying within the cost bound relative to agent execution.
