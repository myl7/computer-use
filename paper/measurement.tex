\section{Measurement}
\label{sec:measure}

We measure both the saving after a program exists and the cost of producing it.
In each attempt, we run the generated program on its source tasks and check whether it completes them.
We call this check \emph{verification}.
We record the costs of successful and failed attempts, and compare program and agent execution on matched fresh inputs.
These measurements provide the online cost profiles and show why low program-use cost alone does not establish payback.

\looseness=-1
We measure compilation and serving costs on seven families: four AndroidWorld tasks \citep{rawles2025androidworld}, two custom LibreOffice tasks in an OSWorld-based container \citep{xie2024osworld}, and a comment-posting task on WebArena's Reddit application \citep{zhou2024webarena}.
The models are GLM 5.3 Flash, DeepSeek Flash, and Qwen 3.8 Flash, with exact recorded identifiers in the Appendix.
Following AutoRPA's translation and construction stages \citep{chen2026autorpa}, we compile $k=3$ completed agent traces and permit bounded repair.
We assume access to task resets and success checks for these source tasks.
For verification, the model extracts bindings from the three source task prompts.
We cache these bindings within the attempt, restore each task's initial state, and require all three tasks to succeed before deployment.
We pass the extracted bindings to the program and judge its results against the source task goals.
This check measures reproduction of the source tasks.
Thirty fresh deployment tasks provide a separate evaluation, including model-based binding extraction.
We subtract the measured no-task harness cost from agent runs, and keep every recorded compilation and repair charge.
The reported costs exclude calls without saved records.
Appendix~\ref{app:measurement-details} describes the verification steps, cost calculations, repeated compilations, and which records are available.

\subsection{Serving cost}
\label{sec:share}

For a program, setting $h=0$ gives the expected saving per execution
\begin{equation}
s=(1-q)c-c^{\mathrm{prog}},\qquad\text{saving share}=s/c.
\label{eq:saving}
\end{equation}
\looseness=-1
The saving calculation includes extraction cost and one mean-cost fallback per failed program run.
Eleven initial programs pass verification.
Their extraction costs range from $331$ to $724$ tokens and their estimated saving shares from $0.936$ to $0.999$.
Appendix~\ref{app:serving-profiles} reports the profiles used in the experiments.

\label{sec:paired}
\looseness=-1
We use agent replays on the thirty deployment bindings of each of the six verified Android programs, giving $180$ matched-input agent runs (Table~\ref{tab:paired-replays} in Appendix~\ref{app:serving-profiles}).
Their saving shares range from $0.952$ to $0.999$, with $157$ successful agent runs and $178$ successful program runs out of $180$.
E.g., the GLM Calendar program passes all thirty bindings, while the replayed agent passes fourteen.
The replay uses a different emulator profile from the program runs and estimates fallback cost as $qc$; it does not measure an agent resumed after each failed program run.

\subsection{Compilation cost}
\label{sec:compile-cost}

Table~\ref{tab:compile-cost} reports the initial attempt charges and verification on the three source tasks.
Using the recorded successful charge as $C$, the payback count excluding source runs is $C/s$.
Adding $k$ mean-cost source runs gives $(C+kc)/s$.
These ratios exclude earlier failed attempts, extra runs required to collect traces, and replacement after drift.
We report cost ratios without rounding up to whole uses.
Rounding up gives the number of uses required to cover the recorded charge in expectation.
Programs from eleven of the twenty cells with compilation-stage records pass verification.
The other nine attempts fail, including Web DeepSeek's generation failure with an incomplete charge record.
Qwen's refused web request remains outside these twenty cells.

Among DeepSeek attempts with complete charge records, failed attempts have median cost $1701$K tokens, compared with $259$K for successful attempts, a $6.57$-fold difference across families.
Qwen's Calc attempt costs $3054$K tokens and still fails the first source task after three refinements.
This comparison does not identify the within-family cost effect of failure.
After successful compilation, the payback count excluding source runs ranges from $1.389$ to $15.488$ uses across these programs.
Thus low execution cost can still require many reuses to pay back compilation.
